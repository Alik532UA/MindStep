### 🛡️ Розробка та Архітектура (Svelte 5 Standards)

#### 1. Якість коду (Checklist)
* **Single Source of Truth (SSoT):** Уникай дублювання стану. Використовуй `$derived` для обчислюваних значень замість ручного оновлення через `$effect`.
* **Runes Usage:** Використовуй `$state`, `$derived`, `$effect` замість Svelte 4 stores у бізнес-логіці компонентів.
* **URL as State:** Якщо стан має зберегтися після F5 (фільтри, таби), записуй його в URL (Search Params).
* **Separation of Concerns:** "Важка" логіка виноситься у `+page.server.ts` або в окремі класи-контролери (`.svelte.ts`). UI не містить бізнес-логіки.
* **Snippets over Props:** Для передачі частин UI використовуй `{#snippet}`.

#### 2. Безпека та Стабільність
* **Keyed Blocks (Обережно):** Використовуй `{#key id}` для повного перерендерингу компонента лише як **крайній захід**. Віддавай перевагу правильному SSoT.
* **Error Boundaries:** Критичні частини UI захищай через `<svelte:boundary>` або `+error.svelte`.
* **Комплексність:** Рішення має бути системним. Не роби поверхневих виправлень ("латок"), усувай корінь проблеми.
