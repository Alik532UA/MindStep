# План покращення архітектури MindStep (v0.0)

Цей документ є дорожньою картою для стабілізації, масштабування та спрощення розуміння коду AI-агентами та розробниками.

---

## Частина 1: Комплексний аудит коду

### 1. Управління Станом (State & Reactivity) — Оцінка: 85/100
*Міграція на Runes завершена на 90%, але залишаються нюанси синхронізації.*
- [x] **SSoT:** Основні стори переведено в класи-руни.
- [ ] **Derived Discipline:** Перевірити `src/lib/stores/gameState.svelte.ts` на наявність ручного оновлення полів, які можуть бути `$derived`.
- [x] **Runes Usage:** Використовується `$state` для об'єктів.
- [ ] **URL as State:** Параметри гри (розмір дошки, режим) частково в URL, але фільтри або активні вкладки налаштувань ще ні.

### 2. Архітектура та Потік Даних (Architecture) — Оцінка: 70/100
*Поділ на Logic/Visual потребує суворішого контролю.*
- [ ] **Server-First:** Логіка онлайн-кімнат у Firestore, але валідація ходів на сервері (SvelteKit) може бути посилена.
- [x] **Type Safety:** TypeScript використовується всюди.
- [ ] **Unidirectional Flow:** Іноді компоненти дошки намагаються напряму змінювати стан через `bind:`, замість виклику методів контролера.

### 3. Чистота та Побічні Ефекти (Side Effects) — Оцінка: 75/100
- [ ] **Effect Isolation:** Перевірити `$effect` у `GamePageLayout.svelte` на предмет зайвої логіки.
- [x] **No State in Effects:** Загалом дотримується, але треба перевірити логіку таймерів.
- [x] **Cleanup Function:** Перевірено в сервісах підписок.

### 4. Компоненти та UI (Component Design) — Оцінка: 65/100
*Багато компонентів ще використовують старий підхід з багатьма пропсами.*
- [ ] **Snippets over Props:** Почати міграцію `FlexibleMenu` та віджетів на Snippets.
- [x] **Headless Logic:** `LobbyController` — гарний приклад, треба поширити на `GameController`.
- [x] **Locality of Behavior:** Дотримується.

### 5. Продуктивність та Стабільність (Performance & Stability) — Оцінка: 80/100
- [x] **Keyed Blocks:** Використовується для рендеру дошки.
- [ ] **Error Boundaries:** Додати більше `<svelte:boundary>` навколо віджетів.
- [x] **Lazy Loading:** Використовується для динамічних імпортів режимів.

### 6. Безпека та Доступність (Security & A11y) — Оцінка: 85/100
- [x] **HTML Injection:** `{@html}` майже не використовується.
- [ ] **Interactive Elements:** Деякі div-іконки потребують `role="button"`.

## Частина 2: Пункти для покращення та Список проблем

### Специфічні вимоги (Mandates)
1. ⚠️ **Ізоляція Board/Logic:** `game-board` НЕ має викликати методи, що змінюють `center-info` напряму. Тільки через `GameController`.
2. ⚠️ **Незалежність режимів:** Рефакторинг `virtual-player` має відбуватися через спільний `BaseGameController`, щоб не зламати `local`.
3. ⚠️ **Коментарі-застереження:** Ігнорування коментарів типу `// CRITICAL: DO NOT MOVE THIS` заборонено.

## Мета для AI Агента
Після реалізації цього плану:
- **Зрозумілість:** Чіткий поділ на "що ми бачимо" (UI) та "як це працює" (Controller).
- **Масштабованість:** Нові режими гри додаються через наслідування `BaseGameController`.
- **Передбачуваність:** Менше побічних ефектів у `$effect`, більше декларативної логіки у `$derived`.
