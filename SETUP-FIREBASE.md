# Налаштування Firebase — що лишилося зробити руками

## Викладення правил доступу — **уже працює**

Секрет `FIREBASE_SERVICE_ACCOUNT` у цьому репозиторії стоїть із серпня 2026,
ідентифікатор проєкту береться з `VITE_FIREBASE_PROJECT_ID`. Джоб
`publish-rules` виконається на наступному ж пуші в `main`.

Переконатися:

```bash
gh secret list -R Alik532UA/MindStep
gh run list -R Alik532UA/MindStep --limit 1
```

## Прибирання покинутих кімнат — **треба увімкнути дві політики**

Кімнату видаляє той, хто виходить останнім, а прострочену — її господар,
коли відкриває лобі. Обидва шляхи працюють уже зараз і нічого не потребують.

Але той, хто **закрив вкладку й не повернувся**, не зробить ні того, ні
іншого. Для таких кімнат є поле `expiresAt` (доба після останньої дії) — і щоб
воно на щось впливало, у Firestore треба ввімкнути **TTL-політику**. Сама база
нічого за цим полем не робить, доки політики немає: це просто ще одне поле.

### Як увімкнути — одна кнопка

Консоль для цього не потрібна: сервісний акаунт у секретах цього репозиторію
вже є, а Firestore має для TTL звичайний REST API.

**Крок 1 — подивитися, що є зараз** (нічого не міняє):

1. вкладка **Actions** у репозиторії на GitHub;
2. зліва обрати **Firestore TTL**;
3. **Run workflow** → перемикач `apply` лишити **вимкненим** → **Run
   workflow**;
4. відкрити прогін і прочитати вивід кроку «TTL-політики». Для кожної з двох
   груп буде стан: `НЕМАЄ`, `CREATING` або `ACTIVE`.

**Крок 2 — увімкнути:** те саме, але перемикач `apply` **увімкнути**.

Те саме з термінала, якщо зручніше:

```bash
gh workflow run "Firestore TTL" -R Alik532UA/MindStep -f apply=true
gh run watch -R Alik532UA/MindStep
```

> **Чому окремим натисканням, а не на кожному пуші.** Увімкнена політика
> означає, що база ПОЧНЕ ВИДАЛЯТИ документи. Таке не робиться як побічний
> ефект коміту: рішення ухвалює людина, а прогін лише виконує його й лишає
> слід у журналі Actions.

Політика вмикається не миттєво: стан `CREATING` переходить в `ACTIVE` за
кілька хвилин, а перше видалення може статися протягом доби після настання
часу — Firestore не обіцяє миттєвості.

### Якщо все-таки хочеться руками

1. відкрити <https://console.firebase.google.com/project/stay-on-the-board/firestore>
2. у верхньому ряду вкладок — **TTL**;
3. **Create policy**, двічі: група `rooms` і група `moves`, поле
   `expiresAt` в обох.

### Чому друга потрібна

Firestore **не видаляє підколекції** разом із батьківським документом. Кімната
зникає, а її `rooms/{id}/moves/*` лишаються сиротами — і дістатися до них потім
нічим, бо шлях починається з ідентифікатора кімнати, якої вже немає.

Стерти ходи не може навіть господар: журнал append-only за побудовою
(`firestore.rules`, `allow update, delete: if false` — подія, яку можна
видалити, не є подією). Отже прибрати їх може лише політика на боці бази.

> **Поле в ходах з'явиться не одразу.** `expiresAt` зараз пишеться в документ
> кімнати. Ходи, записані до цієї зміни, поля не мають, і політика їх не
> побачить — це відомий залишок, а не поломка. Кожен новий хід його
> матиме, коли в `FirestoreMatchLog` додадуть те саме поле; доти друга
> політика стоїть «про запас» і нічого не ламає.

### Перевірити, що політики ввімкнулися

Той самий воркфлоу з **вимкненим** `apply` — він друкує поточний стан кожної
політики й нічого не міняє. Має бути `ACTIVE` для обох.

Побачити результат на самих даних складніше: видалення асинхронне й
розтягнуте. Найпростіше — створити кімнату, дочекатися доби й подивитися, чи
зникла вона з `rooms` у консолі, вкладка **Data**.

## Чому це не частина звичайного деплою

TTL-політика — налаштування **бази**, а не застосунку: оголосити її в
`firestore.rules` чи `firebase.json` неможливо. Тому вона живе окремим
воркфлоу, який запускають руками.

Сам виклик робить [`scripts/firestore-ttl.mjs`](scripts/firestore-ttl.mjs):
підписує JWT приватним ключем сервісного акаунта, міняє його на токен і
звертається до Firestore Admin API. Жодної бібліотеки — лише вбудований
`crypto`.

Локально його теж можна запустити, якщо ключ є під рукою:

Локально його теж можна запустити, якщо ключ є під рукою. Спершу показати
стан:

```bash
GOOGLE_APPLICATION_CREDENTIALS=/шлях/до/ключа.json FIREBASE_PROJECT=stay-on-the-board node scripts/firestore-ttl.mjs
```

І окремо — увімкнути:

```bash
GOOGLE_APPLICATION_CREDENTIALS=/шлях/до/ключа.json FIREBASE_PROJECT=stay-on-the-board node scripts/firestore-ttl.mjs --apply
```
